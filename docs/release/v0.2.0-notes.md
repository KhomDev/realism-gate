# realism-gate 0.2.0

realism-gate reads a Foundry proof of concept and flags what makes a passing
test prove less than it claims: privileged pranks, cheatcode-written state,
assertions that cannot fail, gains measured without a baseline. It never runs
the test and never touches the network.

This release is about getting it where PoCs are written and reviewed, and
about saying how often it is right.

## Install in seconds, no Rust needed

```bash
cargo binstall realism-gate
```

Or take an archive from this release (Linux builds are now static musl, for
x86-64 and arm64; macOS x86-64 and arm64; Windows x86-64) and check it:

```bash
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify <archive> --repo KhomDev/realism-gate
```

`cargo install realism-gate --locked` works too, now that the crate is on
crates.io.

## One line in CI

```yaml
- uses: KhomDev/realism-gate@v0
  with:
    path: test/
```

The action downloads and checksum-verifies the binary, writes the results to
the job summary, keeps a single pull-request comment up to date, and by
default reports only the files a pull request changes. On a fork's pull
request, whose token cannot comment, it falls back to the job summary
without failing. [docs/ci.md](../ci.md) has every input and a safe pattern
for commenting on forks.

## How often a flag is right

A sample of every rule's flags was read in context and labelled, on three
pinned corpora: the one the rules were built against, 70 PoCs added to it
later, and a different corpus never used for tuning. Full tables with 95%
intervals: [docs/precision.md](../precision.md). In short:

- Most rules were right on every labelled flag. For the no-assertion rule
  that is 61 of 61 across two corpora.
- **RG10 (no-baseline)** was wrong whenever the test had set the starting
  balance itself (`deal`, a logging modifier that zeroes it, a freshly
  deployed contract). Fixed: in-sample it goes from 2 of 5 correct to 2 of 2,
  and on the later files from 2 of 8 to 1 of 1, losing one true positive.
  RG10 never fired on the untouched corpus, so this fix has no out-of-sample
  grade.
- **RG05 (code-replacement)** was right on 2 of 5. It is now a warning, not
  an error, under the release's 80% floor for errors.
- Nothing here measures recall. A clean result still means no known defect
  pattern was found, not that the PoC is valid.

The labels, the seed, the corpus hashes and the script that turns them into
these numbers are in `eval/`, and CI regenerates and compares them on every
change.

## Also new

- `--format markdown`; a documented JSON schema
  ([docs/output-schema.json](../output-schema.json)) checked by the tests.
- `realism-gate.toml` for per-rule severity and path excludes, with
  `--severity`, `--exclude`, `--config` and `--no-config`.
- `--changed-since REF` to report only what changed.
- `// realism-gate: allow RG11 <reason>` without parentheses; ignored allow
  comments (no reason) are counted in the output.

## Upgrading from 0.1.0

- RG05 findings are warnings: a run that failed only on RG05 now passes at
  the default `--fail-on error`. Restore the old level with
  `--severity RG05=error`.
- Linux archives are `*-unknown-linux-musl` instead of `*-unknown-linux-gnu`.
- The action's `paths` and `upload-sarif` inputs are now `path` and `sarif`;
  the old names still work. `@v0.1.0` keeps working as before.

The full list is in [CHANGELOG.md](../../CHANGELOG.md).
