# v0.2.0 baseline: realism-gate 0.1.0 as released

This is the reference point for every "before → after" claim in the v0.2.0
release notes, the changelog and the article. It describes the code at tag
`v0.1.0` (commit `10c0f07`, which is also `main` when v0.2.0 work started) and
the binaries attached to the v0.1.0 GitHub release.

Every number below comes from a committed script and a committed or
hash-pinned input. The command that produced it is next to it.

## What the brief assumed, and what is actually there

The v0.2.0 brief describes 0.1.0 as installable only with
`cargo install --locked --git`. The repository says otherwise, and the plan
was adjusted to build on what exists instead of replacing it:

| Brief | Actually in 0.1.0 |
|---|---|
| installs only from git | the v0.1.0 GitHub release has prebuilt archives for five targets plus `SHA256SUMS` and build-provenance attestations (`.github/workflows/release.yml`) |
| needs `--format json` and `sarif` | `--format text\|json\|sarif` exist; JSON is schema 1 |
| needs inline suppressions | `// realism-gate: allow(RGxx) reason` exists; a reason is mandatory and suppressed findings are counted |
| needs an action | a composite `action.yml` exists (inputs `paths`, `fail-on`, `declaration`, `args`, `upload-sarif`, `version`) |
| not on crates.io | correct: `realism-gate` is not published |

What 0.1.0 does not have, and v0.2.0 adds: a crates.io package, musl Linux
builds and cargo-binstall metadata, a post-release install check, an action
that works from a moving `@v0` tag with a step summary and a sticky PR comment,
a config file, a changed-files mode, and a measured precision for each rule.

## Name availability (ruling R2)

`cargo search realism-gate` returns nothing for that name, and
`https://crates.io/api/v1/crates/realism-gate` answers
`crate 'realism-gate' does not exist` (checked 2026-11-04). The name is free;
no alternative is needed.

## CLI surface

```text
realism-gate check [PATHS]...      default: ./test if it exists, else .
    --declaration FILE | --no-declaration
    --format text|json|sarif
    -o, --output FILE
    --fail-on error|warn|note|never   (default error)
    --rules RULES / --skip RULES
    --match-test REGEX / --match-contract REGEX
    --show-suppressed
    --color auto|always|never
realism-gate rules [--format text|json]
realism-gate explain RULE [--markdown]
realism-gate init [--force]
```

Exit codes, checked against the fixtures:

| Input | Exit |
|---|---:|
| `check tests/fixtures/good` | 0 |
| `check tests/fixtures/bad` | 1 |
| a path that does not exist | 2 |
| a directory with no `.sol` files | 2 |
| an unknown `--format` value | 2 |

Rules: RG01-RG14, as listed by `realism-gate rules`. Maximum severities: error
for RG01, RG04, RG05, RG06, RG08, RG09, RG12; warn for RG02, RG03, RG07, RG10,
RG11, RG13; note for RG14.

## Size, speed and install

All measured on one Windows 11 x86-64 machine with 8 logical CPUs. Figures
from different machines are not compared.

| | Value | Source |
|---|---:|---|
| `realism-gate.exe` from the v0.1.0 release | 4,546,560 bytes | `eval/perf/v0.1.0-windows-x86_64.json` |
| release archives (five targets) | 3,272,987 - 3,709,185 bytes | `eval/perf/v0.1.0-assets.json` |
| full corpus, median of 7 runs after a warm-up | 848.8 ms | `eval/perf/v0.1.0-windows-x86_64.json` |
| install without Rust: download archive + `SHA256SUMS`, verify, unpack, `--version` | 2.6 - 2.9 s (3 runs) | `eval/perf/v0.1.0-install-windows-x86_64.jsonl` |
| install with Rust: `cargo install --locked --git ... --tag v0.1.0` | not measured | see below |

Commands:

```bash
python scripts/measure-perf.py <path-to-v0.1.0-binary> v0.1.0-release-windows eval/perf/v0.1.0-windows-x86_64.json
bash scripts/release-assets.sh v0.1.0 > eval/perf/v0.1.0-assets.json
bash scripts/measure-install.sh prebuilt v0.1.0 x86_64-pc-windows-msvc
```

The from-source install could not be timed on this host: two attempts failed
with "the process cannot access the file because it is being used by another
process" (os error 32) while writing build-script fingerprints, a Windows
file-locking problem unrelated to the crate. Rather than publish a number from
a different machine, the baseline leaves it out. The no-Rust path that 0.1.0
offers is the manual archive download above, which needs `gh` or `curl` and
four commands; there is no `cargo binstall` support and no crates.io package.
